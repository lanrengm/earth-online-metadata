# 架构决策记录（防漂移）

> 目的：把「为什么这样做、什么不能改」固化下来，保证多会话 AI 开发不漂移。
> 规则：**改架构必先改本文档**；新会话先读 AGENTS.md 与本文档再动手。

## 1. 站点框架：Astro 7 + React 19 岛屿（2026-09-18）

- **决策**：Astro 静态输出为主，交互处（工具页、文章内嵌组件）用 React 岛屿；文章用 MDX。
- **为什么**：内容站（博客为主）默认零 JS；React 生态对 AI 生成命中率最高（AI-first 核心考量）。
- **不能做**：不引入 Next.js/Vue；不把站点改成全 SPA。

## 2. 主页跳转：手写 meta refresh，不用 Astro redirects（2026-09-18）

- **决策**：`src/pages/index.astro` 手写 `<meta http-equiv="refresh">` 跳 `/tools/`。
- **为什么**：Astro 的 `redirects` 生成的跳转**不带 base 前缀**（`/tools/`），部署到 gh-pages 子路径后 404。
- **不能做**：不要把 redirects 配置加回 astro.config.mjs。

## 3. base 路径与链接（2026-09-18）

- **决策**：部署于 `https://lanrengm.github.io/earth-online-metadata/`，`base: '/earth-online-metadata'`；页面内所有链接经 `withBase()`（`src/lib/paths.js`）。
- **不能做**：模板里硬编码 `/tools/`、`/articles/` 等根路径链接。

## 4. 样式体系（2026-09-18）

- **决策**：`src/styles/tokens.css` 是设计令牌与全局外壳样式的唯一来源（fnos/M3 风格根基）；页面级样式用 scoped `<style>`；React 岛屿样式写在宿主页 `<style is:global>`。
- **为什么**：Astro scoped 选择器打不进岛屿 DOM，岛屿样式必须全局；集中写在使用它的宿主页，避免散落。
- **不能做**：不引入 Tailwind / CSS-in-JS 库；不另建第二套颜色变量。

## 5. 主题机制（2026-09-18）

- **决策**：亮/暗/跟随系统三态循环；偏好存 `localStorage('eo_theme')`；首屏防闪脚本内联在 `Base.astro` 的 `<head>`；切换逻辑在 `AppNav.astro` 底部 `<script>`。
- **不能做**：防闪脚本不能移出 head 内联（会 FOUC）；两处脚本职责不要互换。

## 6. 内容与工具管线（2026-09-18）

- **文章**：`src/content/articles/*.mdx` + `src/content.config.ts` 的 zod schema 校验；列表/详情页自动生成。
- **工具**：React 组件 + `src/pages/tools/<slug>.astro` + `src/tools/registry.js` 注册一条即上架。
- **为什么**：填空式扩展是 AI-first 的核心——AI 不需要理解全项目就能正确添加内容。
- **不能做**：不要为少量内容引入额外抽象层（CMS、数据库、用例层）。

## 7. 自动化验证分层（2026-09-18，升级于同日）

- **决策**：验证分四层，一条 `npm run verify` 跑完：ESLint（代码分析）→ astro check（类型）→ build（路由/schema）→ Vitest（测试）。
- **测试盘点**（`tests/`）：
  - `paths.test.js` — withBase 前缀逻辑（两种 base 形态）
  - `registry.test.js` — 工具注册表守卫（slug 唯一/kebab-case/字段完整）
  - `content.test.js` — 文章 frontmatter 守卫（必填字段/日期格式/标题唯一）
  - `smoke.dist.test.js` — **build 之后**跑的产物冒烟（主页跳转 base 前缀、关键路由存在、无裸根路径链接）
- **为什么分层**：越早的层反馈越快（lint 秒级，build 十秒级），错误在最先可能的时机被拦。
- **不能做**：不跳过任何一层直接提交；smoke 测试依赖 dist，改 CI 步骤顺序时必须保持 build 在 test 之前。

## 8. 开发模式三支柱：AI-first + 文档驱动 + 自动化验证（2026-09-18）

- **决策**：
  1. AI-first——代码全部 AI 写，扩展点做成填空式（.mdx / registry.js），验收由用户做
  2. 文档驱动——AGENTS.md（约定与流程）+ 本文（决策与禁改区）是唯一事实源；**改架构必先改文档**，文档随代码同 commit 更新
  3. 自动化验证——`npm run verify` 是完成标准，CI（ci.yml）在 dev 上跑同款流水线守门
- **新会话工作流**：读文档 → 改代码 → verify 全绿 → 同步文档 → 提交。
- **为什么**：多会话 AI 开发最大的风险是漂移（各会话凭记忆各自理解）；文档提供一致上下文，自动化验证提供客观底线，两者夹住 AI 的输出质量。

## 11. 图表库：ECharts（2026-09-18，替代「待定项」）

- **决策**：选 ECharts 6，`src/components/articles/Chart.jsx` 为**全站唯一封装入口**（按 `echarts/core` 按需注册 Bar/Scatter/Grid/Tooltip/Canvas，控制体积）；`useThemeName()` 观察站点主题切换重渲染；顺序变量（如学历层级）用品牌色十六进制插值色阶，不用彩虹色。
- **为什么**：数据型文章的图表类型覆盖面（堆叠/金字塔/热力/桑基）、配置式写法 AI 命中率高、中文文档全；Recharts 类型不够、visx 底层踩坑多。
- **案例（单篇长文）**：`education-percentile.mdx`（2026-09-19 由「排位实测」与「2030 推算」两篇合并）：全景 100% 堆叠柱 + 「你在这里」定位针（scatter rect + label）+ 同学历幽灵线 + 毛入学率趋势折线（2012-2024 教育部公报）+ 队列外推模型（`scripts/build-education-projection.mjs` 生成 `educationProjection.json`）年份滑块 2020-2030（实测/推算双模式）。
- **数据红线（不可妥协）**：文章数据必须有官方来源与口径说明；自媒体图表一律不直接采信（截图核验实例：其 31-40 列加和超 100%）；本文数据取自《中国人口普查年鉴-2020》表 4-1 原始 xls 并经加和/公报双重校准；推算图必须全程标注「推算」、假设随代码公开、附官方校验锚点（模型 2023 年 2.478 亿 vs 官方「超 2.5 亿」偏差 -0.9%）；模型脚本随仓库开源可复现。
- **不能做**：不绕过 Chart.jsx 直接 init echarts；不在 canvas 里用 color-mix 等浏览器不支持的 CSS 函数（用十六进制插值）；推算数据不得与实测数据在视觉上混淆。

## 12. 图标字体：自托管官方子集（2026-09-18）

- **决策**：弃用 fonts.googleapis.com 运行时请求（国内慢、连字大字符闪烁、与零隐私人设冲突），改为**官方 API 子集化 + 自托管**：`scripts/fetch-icon-font.mjs` 调 css2 API 的 `icon_names` 参数生成子集（52 图标约 75KB），落 `src/styles/fonts/`，`@font-face` + `font-display: block` + preload。
- **加新图标的流程（填空式）**：把图标名追加到 `scripts/fetch-icon-font.mjs` 的 `ICON_NAMES` 列表 → `node scripts/fetch-icon-font.mjs` → 提交更新的 woff2。
- **为何不换 SVG 内联**：可扩展性优先——字体全量机制下加图标只改一个列表；SVG 注册表需维护 path。字体 `font-display: block` 已消除闪烁。
- **授权**：Material Symbols 为 Apache 2.0，`fonts/LICENSE.txt` 随附（子集化属修改，已注明）。

## 13. fnos 视觉规范：无边框色阶分层（2026-09-18）

- **决策**：web 视觉全面对齐 app `es_theme.dart`（fnos 取样）：**卡片/面级元素一律无边框**，靠色阶分层——页底 `--surface`（亮 #F3F3F3 / 暗 #13171A）→ 卡片 `--surface-container-low`（白 / #1A1D22）→ 输入与可交互底 `--surface-container-high`；按钮圆角 12（非胶囊）、次级按钮填充灰阶；输入框填充式、聚焦才出 2px primary 描边（透明等宽边框防跳动）；导航选中态黑白（onSurface）而非品牌色；hover 用阴影/色阶抬升，不用描边。
- **例外**：小控件（主题切换胶囊、复选框、tag）保留胶囊/描边；表格线保留（数据可读性）。
- **不能做**：不要再给卡片/容器加 `border`；不要用 `--border` 令牌（不存在，正确令牌是 `--outline-variant`）。

## 14. 全站两栏骨架：真 flex 左轨道 + 右栏独立滚动（2026-09-19，对标 it-tools，同日二次修订）

- **实测依据**：it-tools.tech 的侧栏并非 fixed，而是 Naive UI Layout 的 in-flow flex 列（`aside.n-layout-sider { position: relative }` 与右栏互为兄弟），外层 `height:100vh; overflow:hidden`，左栏与右栏各自独立滚动。照此实现，侧栏**结构上不可能遮盖 AppBar**，无需 z-index 斗法。
- **骨架**：`.app-shell { display:flex; height:100vh; overflow:hidden }`；`.tool-sidebar` 是 in-flow 列（桌面 `width:0 ⇄ 280px` 过渡收起，右栏 `.app-col { flex:1; overflow-y:auto }` 自动重排，AppNav sticky 于右栏滚动容器内）；视口本身不滚动。
- **窄屏（<1024px）**：侧栏退化为 `position:fixed; top:56px` 的抽屉（从 AppBar 下沿开始），遮罩同样 `top:56px`——AppBar 永远可见可点，不被遮盖；点遮罩/导航项/Esc 收起（焦点在输入框时 Esc 让给搜索）。开合存 `localStorage('eo_sidebar')`，head 内联脚本仅宽屏首屏恢复。
- **侧栏内容（区域替换式）**：品牌色块（primary 纯色，点击回 `/tools/`）常驻；导航区按当前区域替换——工具区显示「全部工具 + category 分组」，文章区（`/articles/*`）显示「全部文章 + 文章标题列表」（`getCollection('articles')` 按日期倒序、当前文高亮，发新文零维护）。
- **版权位置**：全站无独立 Footer 组件，版权与隐私/协议链接常驻侧栏底部（`.ts-footer` flex-shrink:0，fnos 色阶分隔：surface 对 container-low，不用边线）；右栏内容流底部不放页脚。
- **顶栏全局搜索**：`src/components/tools/GlobalSearch.jsx` React 岛屿常驻顶栏，**Ctrl/Cmd+K** 聚焦；工具首页输入经 `window` CustomEvent（`eo:tool-search` + `__eoToolSearch` 初值）实时过滤卡片网格；其他页面弹下拉面板（↑↓ 选择、回车/点击直达）。
- **不能做**：不要把侧栏改回 fixed + margin 伪装推挤；不要恢复右栏/独立 Footer；不要给侧栏或 footer 加 border；不要在工具页内容区再加搜索框。

## 15. 工具二：生涯收入计算器（2026-09-19，MVP）

- **决策**：`/tools/career-earnings/`（slug `career-earnings`，category 个人成长，图标 payments）——输入当前年龄、月薪、退休年龄（预填 63，提示参考男 63/女 55），输出**静态口径**总收入 = 月薪 × 12 × 剩余工龄（`Math.max(0, …)` 兜底已退休情形），附「每年 × 年数」拆解与恢复默认（confirm 确认）。
- **口径**：月薪税前/到手由用户自填自定，工具注明「按你填的口径计」；不做精算。
- **明确不做**（本期排除）：个税与五险一金精算（政策多变易过时）、工资年涨幅假设、通胀折现、年终奖月数、养老金/投资复利、图表。后续按需求迭代再加。
- **工程**：组件 `src/components/tools/EarningsCalculator.jsx`，输入持久化 `localStorage('eo_career_earnings')`（项目工具规则）；fnos 填充式输入 + 无边框结算卡；smoke 测试加 `tools/career-earnings/` 路由。

## 17. 全站视觉改版：群星（Stellaris）科幻风（2026-09-28，修订 #13）

- **决策**：目标用户 18-30 男性，全站换「群星混合方案」科幻风——群星骨架（深空底色 + 扁平面板 + 青/金细线点缀）+ EVE 信息密度气质 + 克制赛博点缀。三方案对比后选定：EVE 高密度布局移动端重做成本过高；纯赛博朋克霓虹与博客长文阅读冲突；群星扁平风与现有 fnos 架构距离最近，tokens.css 换色板即完成大半变身。
- **主题策略**：**暗色为默认**（无保存偏好时直接暗色，不再跟随系统）；亮/暗/跟随系统三态循环按钮保留，亮色主题从简处理（维持原亮色板，不做完整科幻化）。
- **改造范围**：全站统一换肤（工具/属性检定/文章/隐私条款）；**文章正文排版保持安静易读**，只换 chrome（导航/侧栏/卡片/按钮/结果卡）。React 岛屿一律引用 tokens，换色板自动生效，不逐个改组件。
- **对 #13 的修订**：暗色主题下面板从「无边框纯色阶」升级为「1px 细线框 + 切角面板」（`clip-path` 切右上角，Stellaris 面板语言）；亮色主题维持 #13 无边框规则。fnos 的核心分层思想（页面/卡片/可交互三级色阶）保留。侧栏选中项加左侧 2px 主色 accent 线。页面背景暗色下叠加极淡网格纹理（linear-gradient 32px 网格，纯 CSS 零资源）。
- **排版点缀**：新增 `--font-mono` 令牌（系统等宽栈，零下载）用于数值/日期/KBD 等数字场景（结果卡大数字、历史列表、侧栏日期、快捷键徽标），强化 HUD 感。
- **验收修订一：暗色微圆角**：暗色主题内 `--radius-lg/md/sm` 覆写为 4/3/2px——12px 大圆角与切角面板语言打架，纯直角在 Web 上易显廉价，微圆角是 Stellaris 实际面板语言；亮色维持 12px。令牌覆写使全站 React 岛屿自动跟随。
- **验收修订二：品牌块 HUD 化（方案 A）**：暗色下侧栏「17 号玩家」从青色品牌块改为 HUD 暗色面板——透明底 + 底部细线 + 左侧 2px 青 accent + 右上角标装饰 + 等宽小字 `EARTH ONLINE` 与状态行 `PLAYER · 17`（发光状态点）；亮色维持原青色品牌块，副标/状态行仅暗色渲染。
- **验收修订三：滚动条适配**：全局细滚动条（8px、2px 圆角、轨道透明），滑块 `--outline-variant`、hover `--outline`；Firefox 走 `scrollbar-width: thin + scrollbar-color`；亮暗主题各自令牌生效，消灭系统原生滚动条的突兀感。
- **验收修订四：信息架构（修订 #14）**：一级导航（主页/攻略/辅助工具/天赋检测）在侧栏——侧栏成为「品牌块 → 一级区 → 区内条目」的单列主菜单（游戏主菜单式动线），全站唯一高亮源，消除顶栏×侧栏双高亮的位置感冲突；顶栏纯工具化：左 = 汉堡 + 路径式面包屑，右 = 搜索触发器 + 主题切换。GlobalSearch 降级为紧凑触发器（`🔍 Ctrl K` 按钮，点击/Ctrl+K 展开输入与结果面板；非工具首页面板列出全部工具可浏览；工具首页输入仍实时过滤网格，语义不变）。主题按钮 999px 胶囊改随 `--radius-md`。窄屏抽屉不变（抽屉内已含一级导航）。
- **验收修订五：全主题科幻化 + IA 命名定稿**：① 面板语言（细线框+切角、HUD 品牌块、网格底纹、微圆角 4/3/2、accent 线）从暗色专属提升为**全主题统一**，亮色换冷灰蓝浅色板、主色从翠绿 teal 换深青 `#0891b2`（与暗色青同色相），`--grid-line` 令牌分主题取值（置于 `background` 简写之后防重置）；② 一级导航新增**主页**（路由 `/`，空页面 MVP，原跳转 `index.astro` 移除，smoke 测试同步改为断言主页生成）；③ 展示名定稿：**主页 / 攻略（原文章）/ 辅助工具（原在线工具）/ 天赋检测（原属性检定）**，路由 slug 不变；④ 顶栏改**路径式面包屑**（`天赋检测/视觉反应`，Base 传 `title` 给 AppNav 拼接，一级页只显区域名，超长省略号）；⑤ 一级页删 `.page-title` 大标题、`.page-sub` 小标题改引用样式（左 2px accent 竖线 + muted）；详情页保留大标题；⑥ 侧栏版权区与侧栏同底色，`border-top` 分割线区分边界。
- **验收修订六：卡片信息层级（辅助工具/天赋检测网格）**：废除 48px primary-container 大色块图标容器（与侧栏图标纯冗余、满屏主色失焦），图标降为 20px `--outline` 色 与标题同行内联；卡片标题改 `--on-surface`，hover 时边框 + 标题 + 图标转 primary——主色回归「状态与交互」本位；hover 由青色 box-shadow 阴影改为 border-color 过渡（对齐面板语言）。
- **验收修订七：侧栏滚动结构 + 天赋检测分组**：① 侧栏滚动重构——整个侧栏（含品牌块、一级导航、区内导航、版权区）作为一个整体滚动（`.ts-inner` 统一 `overflow-y`）；手机抽屉打开时自动 `scrollIntoView` 定位到选中项（`.ts-item.active` 优先，回退 `.ts-area.active`），免去用户滑动查找；② 天赋检测 17 项按认知领域分 5 组（专业认知域命名）：**加工速度**（视觉/听觉/选择反应、手眼精度）、**工作记忆与空间**（数字广度、N-back、空间记忆、心理旋转）、**知觉与注意**（视觉搜索、时间感知、色觉辨别）、**执行与推理**（Stroop、任务切换、逻辑推理、心算速度）、**决策与自控**（风险偏好、延迟满足）；③ `src/tests/registry.js` 加 `category` 字段（与工具注册表同模式，注册表顺序 = 展示顺序），侧栏分组 it-tools 式可折叠（`expand_more` 箭头旋转，默认展开，状态存 `localStorage('eo_tests_groups')`），页面按组分节展示；图标子集 +1（expand_more → 66 图标 96KB）。
- **性能红线**：禁止 heavy blur/glow/大滤镜/动画循环；纹理只用纯 CSS 渐变；不新增任何字体/图片资源。
- **分期**：Phase 1 换肤（tokens + 主题默认 + 排版点缀）与 Phase 2 组件细节（切角/细线/HUD 装饰）本决策内一次交付；Phase 3 微交互（hover 辉光、扫描线）记入待定项按需再议。
